## 裁剪在地面 / 动画（图组）不生效 —— 根因与统一修法

- 地面根因：地皮着色器用自定义 uniform sampler（uT0..uT6），three 的 texture.offset/repeat 只对材质内置 map 槽生效，对自定义 sampler 完全不参与采样 → UV 裁剪静默失效（1x1 裁剪判据证实：9112→9115 色数没变）。
- 动画根因（次要）：MeshBasicMaterial.map 的 offset/repeat 本应生效，但为消除整类问题也切到协议裁剪；顺带修了覆盖物 textureRect 错拿主贴图裁剪框的 bug。
- 统一修法：`resolve.ts` 新增 `renderTexture(doc, img)` → 桌面端 { path: 协议裁剪URL, rect: null }，浏览器端退回 { path: 原图, rect: cropToUv }。
  - animationParts 主贴图与覆盖物都走 renderTexture（texturePath 已是裁好的图，Viewport3D 不再二次 UV 换算；aspect 用裁剪后图的自然尺寸，天然正确）。
  - groundMesh.loadImageTexture 改用 imageCssUrl，删掉无效的 offset/repeat；imgSig 含 crop 所以地面会重建。
- Viewport3D 容器加 data-anim-host（测试定位用）。
- verify 新增「裁剪影响·地面/动画」探针：1×1 裁剪判据（nativeImage.getBitmap 数 unique 颜色，采样区含网格/文字不可能纯色，用 before/0.5 阈值）+ ground-crop.png / anim-crop.png 人眼复核。地面 9112→2655、动画 6293→1565，均 ok；全量探针 0 失败。
- 修正判据教训：截图字节 diff 不可靠（光照/布局扰动也会变），1x1 退化成纯色才是硬判据。

## 纸片人渲染修复 + 演示录屏（下午）

- **散架根因**：动画编辑器 Viewport3D 的语义是「layout.x/y = 中心到父中心；旋转绕部件中心；pivot 只用于烘焙序列帧不参与定位」。HTML 精灵原来按 pivot 锚点挂图（bottom/top/…），每个部件多/少移半个身高 → 走路姿势下散架。修复：部件 img 一律 `translate(-50%,-50%)` 中心对齐，mirror 时 scaleX(-1)；覆盖物改为「以偏移点为中心的方形（边长 = 部件高×scale，objectFit:fill 拉伸）」。
- **缩放重构**：CharacterSprite 局部坐标固定用画布像素（512 画布=2 世界单位 → 256px/单位），整棵树只在根上做一次 `scale(sx, sy)`；sx = pxPerUnit/256，**sy 还要乘 cos(pitch)**（竖直平面在俯视相机下的正确投影，45° 时 0.707）。此前逐部件乘 u 且没算俯角压缩 → 角色偏高 41%、且垂直不居中。
- **相机取景**：播放时 dist = charH·cos45/(2·tan(fov/2)·0.32)（角色约占屏高 1/3），target.y = charH/2（角色整体居中）。pxPerUnit 改用「相机到角色的实际距离」算（编辑态视角拉远时不再失真）。
- 动画部件全空时画纸片人占位（身体+头），避免"什么都没有"。
- `window.__charMetrics`：每帧暴露 pxPerUnit(Y)/charHeight/screenH/ground/viewport/pitch，供探针与录屏。
- **录屏管线**（环境无 ffmpeg、npm install 被拒）：`npm run record` = `--record` 模式（electron/lib/record.ts：临时工程 Demo → 播放 → 按时间表模拟 WASD → capturePage 逐帧 760px PNG ≈12fps）→ `scripts/frames-to-gif.py`（Pillow 全局调色板 160 色 + 逐帧 delay）→ `.verify/demo.gif`（~2.5MB/6.5s）。
- 实测指标：screenH 177px（屏高 28%），ground 点 (482,402) vs 视口中心 (481,312) → 水平垂直都居中；shot 全绿。
